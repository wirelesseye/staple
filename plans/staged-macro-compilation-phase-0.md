# Staged macro compilation, Phase 0: spike

Breakdown of Phase 0 in [`staged-macro-compilation.md`](staged-macro-compilation.md).
Line references are against `main` at `4d28a844` (2026-10-31).

Phase 0 decides whether compiled macros can run in a separate macro-server
process (Decision 3 of the umbrella plan) and measures what that costs. The
spike code does not merge. What this phase delivers is the findings, written
into this file, and any changes they force in the umbrella plan.

## What already exists

Facts the spike can build on. All were read from the source and none have
been tried yet.

- **Codegen already builds position-independent code.** `create_target_machine`
  uses `RelocMode::PIC` (`staple-compiler/src/codegen/mod.rs:596`), so objects
  may already be linkable into a shared library as they are.
- **Library units exist.** `main` is only emitted when
  `self.unit.emits_main()` (`codegen/lowered/mod.rs:208`). Package builds
  already emit objects without `main` through `emit_unit_object`
  (`codegen/mod.rs:257`, used from `staple-cli/src/compile.rs`). A phase-1
  library can probably start as a unit that does not emit `main`.
- **`main` does the runtime setup.** `emit_main` (`codegen/lowered/mod.rs:2685`)
  sets the GC stack bottom (`__staple_gc_set_stack_bottom`, `gc.ll:900`),
  registers every global GC root, and runs the module initializers. A library
  needs the same setup without `main`.
- **The GC scans the stack conservatively from a recorded bottom**
  (`@__staple_gc_stack_bottom`, `gc.ll:25`, read at `gc.ll:473`). When the
  host calls into the library, the bottom has to be valid for the calling
  thread's stack.
- **Host code already calls compiled Staple functions.** Tests in `lower.rs`
  JIT a module, run `main` for initialization, then call instances through
  their symbols as `unsafe extern "C" fn(*const usize) -> i32`
  (`lower.rs:16190`–`16215`). This shows the instance calling convention a
  shim has to wrap.
- **Staple can't export a C-ABI function.** `extern` blocks only *declare*
  foreign values (`Staple.md`, "Foreign declarations"). Shims have to be
  generated by the compiler, at the lowered or LLVM level.
- **`panic` ends the process.** It writes to stderr and calls `exit 1`
  (`stdlib/std/process.sta:41`). Inside a server that ends the server, so the
  parent has to notice and recover.
- **Linking shells out to `cc`** (`executable_link_command`,
  `staple-cli/src/compile.rs:1003`) and adds `-lm` on Linux.
- **There is no dynamic-loading dependency yet.** `staple-cli/Cargo.toml` would
  need one, for example `libloading`.

## Tasks

The tasks are in dependency order. Tasks 4 and 5 can run in parallel once task 3
works.

### 1. A stand-in phase-1 program

Write a Staple program that represents what a real phase-1 program will need,
without any syntax types (they don't exist at run time yet):

- An "expansion function" `U64 -> U64` that takes a fake syntax handle. It
  builds a `List<String>` from text supplied by the host, joins and transforms
  the strings with ordinary `String` operations, uses a range and an exact
  integer type (`USize`) somewhere, and returns a new handle from the host.
- Host intrinsics declared in an `extern "c"` block, for example
  `spike_text_len: U64 -> USize`, `spike_text_copy: (U64, RawMutPtr<U8>) -> ()`
  and `spike_make_text: (RawPtr<U8>, USize) -> U64`.
- A variant that panics, and a variant that loops forever.

Check that it compiles and runs as an ordinary executable first, using stub C
implementations of the intrinsics. Put the program and the stubs in the spike
branch, for example under `spike/macro-server/`.

### 2. Emit it as a shared library

- Add an internal path, for example a hidden `--emit dylib` in
  `staple-cli/src/compile.rs`. It lowers the program as a unit that does not
  emit `main`, emits the object for the host triple and links it with `cc
  -shared`. Linux and macOS need different flags. Record what each needed.
- Generate one C-ABI shim per entry point, at the LLVM level, as an
  `extern "C"` symbol with a fixed name. Each call should:
  1. set the GC stack bottom to the shim's own frame,
  2. call the instance with the calling convention the `lower.rs` tests use,
  3. return a plain integer.
- Generate one library initializer (`__staple_library_init`) that does what
  `emit_main` does apart from returning: register the GC roots and run the
  module initializers. Factor that code out of `emit_main` instead of copying
  it, if that is easy.
- Check the census assertion in `lower/census.rs:120` ("every executable module
  defines `main`"). It probably needs to accept library units.
- Record any runtime `.ll` (`gc.ll`, `io.ll`, `fs.ll`, `coroutine.ll`,
  `reactive.ll`, see `codegen/runtime.rs`) that doesn't link into a shared
  library, and why.

### 3. A server stub that loads it

- Add a hidden `staple __macro-server <library>` subcommand. It loads the
  library, runs `__staple_library_init`, and reads requests from stdin (one
  entry-point name and one handle per request), then writes results to
  stdout. A trivial line or length-prefixed format is enough. The real wire
  format belongs to Phase 3.
- Supply the intrinsics in two ways and record which works better:
  - **Function-pointer table (preferred by the umbrella plan).** The library
    exports `__staple_library_bind(table)`. The phase-1 program calls
    intrinsics through table entries. That needs a codegen change so that
    calls to those externs go through a global pointer.
  - **Dynamic symbol lookup.** The externs stay undefined in the library
    (`-undefined dynamic_lookup` on macOS, the default on Linux). The server
    binary exports them with `#[unsafe(no_mangle)] extern "C"`, with
    `-rdynamic` or the platform equivalent.
- Handles index a `Vec<String>` arena in the server.

### 4. Failure behavior

Using the panicking and looping variants from task 1:

- **`panic`.** Confirm that the parent sees the server exit with its stderr
  message. Try routing `exit` through a host intrinsic instead. That would let
  the server report the panic and keep running, without reloading the library.
  Record whether it works and what state it leaves behind (GC heap, globals).
- **Non-termination.** The parent kills the server after a timeout and starts
  a new one. Measure how long a restart and reload take.
- **Stack overflow.** Recurse deeply. Confirm the server dies with a signal and
  the parent reports it.
- **Calling twice.** Confirm that a second request after a successful one
  works: the GC state stays valid and initializers don't run again.

### 5. Measurements

On macOS (the development machine) and on Linux if possible, measure with
release builds of `staple`:

1. Time to compile the stand-in program to a shared library, split into front
   end, lowering plus codegen, and link.
2. The same for a closure as large as `@derive_eq`'s
   (`stdlib/std/cmp.sta:176`) and its helpers. Approximate it by copying those
   helpers into an ordinary program, with stubs where syntax types are used.
3. Server startup: spawn, load, init.
4. Round trip per request with requests sent one at a time, and with 1,000
   requests batched.
5. Baseline: the current interpreter expanding `@derive_eq` on a type with 50
   fields, and expanding a file with 1,000 `if` calls (`staple expand`, timed
   end to end).

Record the machine, the commit and the commands next to each number, so the
measurements can be repeated.

### 6. JIT comparison (time-boxed to one day)

Load the same LLVM module into an inkwell `ExecutionEngine` in-process, as the
`lower.rs` tests do, and measure (1) and (4) for that path. This is not meant to
reopen Decision 3. It gives numbers for the in-process mode the umbrella plan
leaves for later.

## Go / no-go criteria

Decision 3 holds if:

- the stand-in library links and runs on macOS and Linux without changing the
  runtime `.ll` files beyond small, contained fixes;
- a panic, a timeout and a stack overflow all come back to the parent as a
  reportable error, and the parent can keep working afterwards;
- the batched round trip is small next to the compile time of a closure (it
  should be well under 1 ms per request);
- the build time for a `@derive_eq`-sized closure is acceptable for a cached,
  once-per-edit cost. Seconds are acceptable and minutes are not. Write down
  the threshold you used.

If a criterion fails, record which one and the evidence, and propose the
change to the umbrella plan (for example, linking an executable per closure
instead of a shared library, or running in-process for trusted libraries).

## Findings

1. **Library builds are dominated by the standard library, not the closure.**
   An `identity`-only library costs 3.2 s (M2) against 3.6 s for the stand-in
   (M1). Two things cause it: the whole program is compiled, and lowering
   seeds every non-generic template eagerly (`lower/worklist.rs:845`). With a
   package graph, prebuilt std objects bring the cost down to 1.6 s (M4). The
   remaining ~1.1 s is the front end checking the whole standard library on
   every build. **Change for the umbrella plan:** phase-1 libraries are built
   against cached std objects, like incremental package builds (Phase 4). To
   go further, Phase 4 should either cache the front end's checked standard
   library or check only the closure's modules.
2. **Per invocation, compiled macros are much faster than the interpreter.**
   The interpreter spends about 0.43 ms per `if` and 0.5 ms per 50-field
   `@derive_eq` (B2, B3). A pipelined compiled call costs about 7 µs of IPC
   plus the macro's own work (R4). This supports template macros (Decision 2)
   for `if`: even in a server, a template filled in by the parent beats both.
3. **Both ways of binding host intrinsics work.**
   - Dynamic lookup: the externs stay undefined (`-undefined dynamic_lookup`)
     and the server exports them (`-Wl,-export_dynamic` from
     `staple-cli/build.rs`).
   - Function table: with `--library-host-symbol`, each foreign declaration
     becomes a thunk that calls through a slot. `__staple_library_bind(resolve)`
     fills the slots by name.

   The table needs no exported symbols in the `staple` binary and fails
   cleanly on a missing symbol. It costs one indirect call per intrinsic.
   **Keep the table (Decision 3 as written).** The thunks and the `exit` trap
   must be *hidden external* definitions, not internal ones. Otherwise calls
   from the prebuilt std object, where `panic` lives, still reach libc
   (fixed in `3e8a4060`).
4. **`exit` can be trapped without restarting the server.**
   - In a library, `exit` gets a body that stores the code and `_longjmp`s
     back to the entry shim, which `_setjmp`ed on entry. Only Staple frames
     are skipped, and Staple has no unwinding, so nothing in Rust is jumped
     over. The GC kept working afterwards (F1).
   - Use `_setjmp`/`_longjmp`. Plain `setjmp` saves the signal mask, which
     costs about 220 ns per call on macOS (R6).
   - Open for Phase 4: values held by the abandoned frames are never dropped
     (fine for GC memory, a leak for anything with a `Drop` that frees
     outside the GC). Also, the panic message goes to stderr instead of
     being returned as data.
5. **The toy ABI and missing IR optimization dominate call cost.** `expand`
   takes 18 µs for a 16-byte input, both in the server and under the JIT
   (R5, R7). Codegen sets `OptimizationLevel::Default` on the target machine
   but runs no IR pass pipeline (`codegen/mod.rs`). Phase 3's ABI should move
   whole byte buffers, not one byte per call. Phase 4 should decide whether
   phase-1 libraries run the IR optimizer: a slower build for faster
   macros.
6. **The JIT isn't worth it for builds.** MCJIT took 1.5 s to compile the
   whole program (M6), the same as object codegen (M1). It also can't reuse
   the cached std objects that make M4 fast, and its calls cost the same
   (R7). The in-process mode the umbrella plan leaves for later should load
   the *same* shared library with `dlopen`, not JIT.
7. **A stack overflow kills the server with Rust's message** (F4). The parent
   has to recognize SIGABRT and SIGSEGV and report "macro overflowed its
   stack" at the invocation. Running each call on a dedicated thread with a
   large stack (the expander uses 256 MB today) would make deep but finite
   recursion work. A guard-page overflow would still kill the process.
8. **Lowering bug, found along the way, not fixed here.** This program
   type-checks (`staple check` passes) but fails to lower with
   "trait `Iterator` for `IntoIterator.Iter, String` is ambiguous at run-time
   types", naming three `String` iterator impls:

   ```staple
   use std.range.range
   def expand = (move words: List<String>) => String :: String.join ", " words
   ```

   Without the `use std.range.range` line it compiles. `standin.sta` works
   around it with a manual loop. This should be fixed on `main`, with a test.
9. **Smaller notes:**
   - `0..n` with `n: USize` infers the `0` as `I32` and fails, while
     `range zero n` with a typed `zero` works.
   - `Buffer` has no public data pointer, so a host can't fill Staple memory
     in bulk. Phase 3 needs an intrinsic or a `std`-internal path for that.
   - Instance symbols include the package path
     (`__staple_mstandin.standin.expand` in a package and
     `__staple_mstandin.expand` without one). Phase 4's shims should be named
     by the compiler, not by the user's module layout.
